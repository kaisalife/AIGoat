# 02 · 团队原子化与团队特化副本

## 一、三种东西，一次厘清

| 概念 | 是什么 | 存在哪 |
| --- | --- | --- |
| 成员（原子个体） | 一个可独立派活的子 agent；`team` 为空也能存在 | `registry.agents` |
| 团队（编组） | 成员之上的分组，带**流程**与**规范** | `registry.teams` |
| 特化副本 | 某成员按某团队规范生成的独立成员，原初员工不受影响 | `registry.agents`（名字 `团队/成员`） |

原子化不是新功能——现状已支持（`team` 是 `Option<String>`，未编队成员单列一组）。
缺的是：**团队规范的载体**、**批量特化**、**副本与原初的可见关系**。

## 二、现状与差距

| 项 | 现状 | 差距 |
| --- | --- | --- |
| 成员独立存在 | 已支持 | 无 |
| 组装进团队 | 已支持（`team` 字段） | 无 |
| 团队流程 | `TeamMeta.workflow`，注入派单说明 | 无 |
| 团队规范 | 无 | 流程讲"顺序"，规范讲"所有人必须遵守的约束"（命名、风格、交付口径），两者不能混 |
| 特化副本 | 无 | 需要一个"一次性把全队落成特化成员"的动作 |
| 副本来源可见 | 无 | 界面要能看出谁是副本、来自谁、是否过期 |

## 三、数据模型改动

### 3.1 `TeamMeta` 增 `spec`

```rust
pub struct TeamMeta {
    #[serde(default)] pub workflow: String,  // 流程：阶段与交接顺序
    #[serde(default)] pub spec: String,      // 规范：全体成员共同遵守的硬约束
}
```

两者语义分开，注入时也分两节。`workflow` 为空但 `spec` 非空时，团队仍保留。

### 3.2 `AgentEntry` / `AgentSpec` 增 `derived_from`

```rust
#[serde(default)] pub derived_from: Option<String>,  // 副本来源的原始成员名
```

- 只记录来源，不记录时间：过期判定复用现成的 `registered_at`——
  **副本的 `registered_at` 早于原初成员的 `registered_at`，即视为过期**
  （原初被改过，副本需要重跑特化）。不新增时间字段。
- `upsert` 透传该字段：`materialize` 写入来源名；界面/变更单的手动 upsert 传
  `None`，等于"用户接管这个条目、它从此算原初成员"（副本标记清掉）。

### 3.3 名字规则放宽（只需放宽这一处）

现状：`registry::upsert` 只允许 ASCII 字母数字与 `-` `_`，因此 `游戏组/reviewer` 写不进去。

新规则（`registry/mod.rs` 的校验函数）：

- 非空；允许 Unicode 字母数字、`-`、`_`、`/`
- 禁止空白、`\ : * ? " < > |`、以 `/` 开头或结尾、连续 `//`、包含 `..`
- 存量名字全部仍然合法（只放宽、不收紧）

### 3.4 文件名的 slug 规则（容易踩的坑）

codex 原生成员会落成 `<CODEX_HOME>/agents/<名>.toml`，`/` 在 Windows 文件名里非法。
所以**注册表主键**可以是 `游戏组/reviewer`，但**落盘 slug** 一律
`name.replace('/', "__")`：

| 用途 | 取值 |
| --- | --- |
| 注册表键、界面显示、派单说明标题 | `游戏组/reviewer` |
| 角色文件名、角色 TOML 的 `name` 字段、`spawn_agent` 的 name | `游戏组__reviewer` |

`role_file_toml` 与 `sync_role_files` 两处统一走 slug 函数；派单说明里对副本额外
注明 codex 调用名。

## 四、副本语义

### 4.1 生成公式

对团队 `T` 的**花名册**（`TeamMeta.roster`）里每个原初成员 `M` 生成副本 `T/M`。
花名册由挑人时给出（`members`），成员可以来自任何团队、也可以未编队——**挑人
只生成副本，原初成员不动，同一个人可被多个团队同时挑中**。

| 字段 | 取值 |
| --- | --- |
| `kind` / `path` / `model` / `skills` / `mcp_servers` | 原样继承 `M` |
| `team` | `T` |
| `desc` | `M.desc` + `（T 特化）` |
| `prompt` | `M.prompt` + 团队规范段 + 团队流程摘要（见下） |
| `derived_from` | `M` |

`prompt` 合成顺序固定，便于人工核对：

```
<原角色提示词>

## 团队规范（<T>）
<spec 全文>

## 团队流程（<T>）
<workflow 全文>
```

### 4.2 原初员工零改动（硬约束）

特化**只写** `T/M` 这几条，绝不碰 `M`：

- 不改 `M.team`（仍留在原团队或未编队）
- 不改 `M.prompt` / `M.desc` / `M.model`
- 不改 `M.registered_at`

### 4.3 幂等与清理

- 重跑覆盖同名副本（`upsert` 天然幂等），`registered_at` 刷新 → 过期标记自动消失。
- 花名册持久化在团队上：不传 `members` 时按已存花名册重建（界面「特化」按钮走这条）；
  `members: []` = 清空编制，配合 `prune` 一并删掉全部副本。
- `prune=true`：删除该团队里不在花名册中的副本。
- 副本本身不可再被挑（避免 `T/T/M`）：执行时对副本报错。

## 五、CLI 扩展（`aigoat team-apply` 变更单）

新增两种 op，沿用现有 `SpecFile` / 报告结构：

```json
{ "ops": [
  { "op": "spec", "team": "游戏组", "spec": "命名用蛇形；所有交付物必须写进 assets/；评审不通过不得进入下一阶段" },
  { "op": "materialize", "team": "关卡组", "members": ["reviewer", "builder"], "prune": true }
] }
```

- `spec`：写团队规范（空串 = 清除）。
- `materialize`：把该团队全部非副本成员特化一遍，返回每条副本的 `applied` 明细。
- `team-list` 输出加副本视角：`derivedFrom`、`derivedStale`（见 3.2 的过期判定），
  让 codex 自己就能回答"副本该不该刷新"。

## 六、派单说明注入（`registry/instructions.rs`）

`push_team_overview` 现在只输出成员清单 + 工作流；改为三段：

```
- **游戏组**：reviewer、builder
  - 团队规范：
    <spec 逐行缩进>
  - 工作流：
    <workflow 逐行缩进>
```

副本不单独开一节：它已经在团队清单里，并带有 `（特化）` 后缀，主 agent 按名派活即可。

## 九、验证

1. `cargo test`：`materialize.rs` 三组用例（原初字段不变、重跑幂等、副本不再特化）。
2. 名字校验单测：`游戏组/reviewer` 通过；`a/b/c` 通过；`a//b`、`/a`、`a\b` 拒绝；
   存量 `reviewer` 仍通过。
3. slug 单测：`游戏组/reviewer` → `游戏组__reviewer`；角色文件确实落在
   `<CODEX_HOME>/agents/游戏组__reviewer.toml`。
4. 端到端：建团队 → `spec` → `materialize` → `team-list` 看到副本且 `derivedStale=false`
   → 改原初成员 → 再 `team-list`，`derivedStale=true` → 重跑 `materialize` 恢复 false。
5. `cargo fmt --check`、`cargo clippy -- -D warnings`、`powershell -File tools\verify.ps1`。
6. 界面手验：团队卡编辑规范、点特化、成员卡出现副本徽标；原初卡片字段完全未变。

## 十、风险与取舍

| 风险 | 处置 |
| --- | --- |
| 副本数量膨胀（团队 × 成员） | 只按团队显式触发，不自动特化；`prune` 清理；界面显示副本数 |
| 名字放宽后历史文件名冲突 | slug 只做 `/` → `__`，若与已有名字撞车，`upsert` 后写覆盖前，执行前做一次冲突检查并报错 |
| codex 原生副本要重连才生效 | 与现有 codex 成员一致：技能里提醒用户点「重连」 |
| 手改副本被下次特化覆盖 | 表单顶部明示；副本定位是"派生物"，不是编辑入口 |
| `registry/mod.rs` 已超 200 行 | 本次只加必要字段与校验；特化逻辑全部放新文件 `materialize.rs` |

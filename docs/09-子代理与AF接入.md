# 09 · 子代理展示与 AF 子 Agent 接入

> 抄 dsh：`packages/client/ui-subagent/src/client/`（lineage 面包屑/后代目录/只读 tab）｜协议：`subAgentActivity`＋`collabAgentToolCall`＋多 thread｜AIGoat 独有：**AF 规范注册表**｜决策：**改**（两套子代理体系分流展示）

## 1. 两套"子代理"的概念厘清（本板块的核心设计决策）

| | codex 原生子代理 | AF 子 Agent（AIGoat 独有） |
|---|---|---|
| 本体 | codex 内部 thread（`agent_thread_id`） | 用户注册的无头一次性进程（`<exe> --agent task.json --out report.json`） |
| 协议 | `subAgentActivity` Item＋`collabAgentToolCall` | shell 派单：主 agent 执行命令→表现为 `commandExecution` Item |
| 管理 | 无需注册 | `~/.agent-registry/registry.json`＋设置中心 CRUD |
| 展示 | lineage 面包屑＋后代目录＋只读 tab | 命令卡（05）＋设置中心注册表 |

**分流规则**：`subAgentActivity`/`collabAgentToolCall` 走 codex 原生展示；
AF 派单表现为普通命令执行，其"派单说明"由 `developerInstructions` 注入
（现有机制不动）。两者不混淆、不虚构。

## 2. dsh 的设计（ui-subagent）

- 会话头部 **lineage 面包屑**：父→子链路，hover 展开后代目录（懒加载嵌套）。
- `@` 引用子代理。
- 右栏**子会话只读 tab**：完整事件流只读查看，可「续问」（fork 出新会话）/Stop。

## 3. codex 协议支持

- `subAgentActivity` Item：带 `agent_thread_id`＋`agent_path`——**已映射**
  （map.rs），前端现为徽章点击跳线程，保留并升级。
- 多 thread 订阅：桥接层支持多 Session（P3 已验证），前端需支持"订阅非活跃
  线程"——当前 shell 只订当前线程，需加旁路订阅通道（17 期 `bridge_subscribe`
  或复用现有 agent-event 通道按 threadId 分流，**取后者**：事件已带线程上下文，
  store 侧按 id 路由即可，零新命令）。

### 4.2 关键设计

- **LineageBreadcrumb**：当前线程若有父（fork/subagent 来源），会话头显示
  `父名 ▸ 当前名`；hover 弹 DescendantTree（数据：`thread/list` 全量 +
  `subAgentActivity` 的 agent_thread_id 建边；懒加载＝首层展开才拉子线程
  `thread/read`）。
- **只读 tab**：右栏 dock 注册 `subagent-readonly` tab 类型（10），
  打开即旁路订阅该线程；内部复用 ChatView 组件树（`readonly` prop 禁用
  composer 与审批应答）。续问 = forkThread(该线程) 并激活；Stop 走
  interrupt(该线程)。
- **徽章保留**：SubAgentActivity 在消息流的徽章点击 → 打开只读 tab
  （替代现在的"跳转切换线程"——不打断当前会话，dsh 同款）。
- **AF 增强项**（可选，低成本）：识别 commandExecution 的命令文本若匹配
  已注册 AF agent 的调用协议（`<exe> --agent`），命令卡加 AF 徽标与
  该 agent 的能力摘要（读注册表本地匹配，纯前端展示增强）。

### 5.1 「零新命令」的落地方式

09 号文件 §3 说"取复用 agent-event 按 threadId 分流"这条。落地就是它，
而且比预想的更简单：**06 号板块的账本已经按 threadId 存了所有事件**
（`store/ledger.ts` 的 `rows: Record<threadId, LedgerRow[]>`）。所以

- 血缘树 = 从账本算出来的（`store/subagents.ts` 的 `buildTree`）
- 只读 tab 的内容 = ingest 时落下的**每线程 TurnState 快照**

没有新协议方法、没有新命令、没有第二条订阅通道。

### 5.2 修掉一个会立刻咬人的 bug

改造前 `ingest` 不看 threadId，一律把事件灌进唯一的 `turn`。而
`agent-event` 那一条流里混着**所有线程**的事件 —— 子代理在自己的线程里跑，
它的思考、正文、工具调用会全部插进**主会话的消息流**。

这不是"将来多线程才会遇到"，而是**只要用过一次子代理就会遇到**。
现在按 `threadId` 分流（`slices/ingestForeign.ts`）。

### 5.3 别的线程请求应答时，为什么是"自动拒绝"

子代理的审批 / 提问落到主会话的 composer 上是错的（那是别人的线程）。
但**直接丢弃更糟**：协议上那是"等一个应答"的请求，不回它那一轮永远悬着。

所以选"自动拒绝 + 说明"：

| 做法 | 后果 |
|---|---|
| 丢弃 | 那一轮永久卡死，模型停住 |
| 自动批准 | 真的放行了一个用户没看过的命令 |
| **自动拒绝 + 提示** | 子代理被拒，用户在提示行里知道发生过什么 |

客户端工具（`toolCallRequested`）例外——那本来就是宿主自己的活，直接执行。

### 5.4 父节点靠路径前缀认

协议**没有** parent id，只有层级化的 `agentPath`（`root/a/b`），而线程 id 是
uuid、和路径末段对不上。所以父 = "路径是本节点路径的**最长真前缀**的那个节点"。
认不出来就当根：宁可显示成顶层，也不要挂错人。

快照上限 5 个线程（`store/snapshots.ts`），淘汰"最近最少活跃"的那个——
用户刚看过的一个子线程，哪怕创建得早，也比半小时前冒出来没人看的更该留着。

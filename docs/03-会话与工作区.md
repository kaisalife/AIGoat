语义坑（写进代码注释）：`thread/revert` 只回退对话历史**不回退本地文件**，
且须先 interrupt 运行中回合；`threadSection` 是**会话内**分区（组织长会话），
不是会话列表文件夹——别用错层级。

发现其中 5 项确实没做，已在本轮全部补上（判断见 §4.1）。

### 4.1 实现期的四个关键判断

**① 状态点就地打补丁，不重拉列表。**
`thread/status/changed` 到达时只改那一条的 `status` 字段。重拉列表会把用户
正在拖的行、展开的归档区全部抖一下，而状态点只需要一个字段。

**② 状态以协议 `status` 为权威，`preview` 推断降级成兜底。**
`ThreadStatus` 有真信号（`active` / `idle` / `systemError` + `activeFlags`），
改造前只能靠「preview 为空 = 在跑」猜。现在以协议为准；老会话没带 status
字段时才看 preview。

**③ 排序存 id 列表而非索引。**
会话会被删。索引一删就全错位；按 id 存的话被删的那几条直接被忽略。
搜索结果里**禁用拖拽**——那是临时视图，在它里面重排会把用户搞不懂的
顺序写进设置里。

**④ revert 放在回合头，不放在会话行菜单。**
回滚要指定"哪一回之前"，而回合只在消息流里可见。放行菜单里，用户得先去
Trajectory 记下回合 id 再回来点菜单——技术上能实现，但不是能用的交互。
第一回合不给按钮（"它之前"等于清空整个会话，清空有独立路径）。

**⑤ fork 完紧接着 resume 一次。**
协议明确 fork **不带历史**。不补这一下，用户看到的是一个空白的新会话，
会以为历史被吞了。

验收：列表操作（建/切/删/归档/重命名/fork/置顶/拖拽）全链路可用；
刷新后顺序与置顶保持；SidebarLeft 拆分后无文件超 200 行。

# 08 · 输入与命令系统

> 抄 dsh：`packages/client/ui-input-trigger/`＋`ui-commands/`＋`ui-reference/`｜协议：skills/list＋fuzzyFileSearch/*＋compact/start 等｜决策：**抄**

## 1. dsh 的设计

- **触发管线**：输入框内的 `/`、`@`（等触发符）进入统一管线——
  **三态派发**：`popupSelect`（弹层选择）/ `action`（立即执行）/ `execute`
  （提交时执行）；fuzzy 搜索 + 分组 sticky 标题；所有弹层共享 composer 焦点模型。
- **命令目录**：命令注册表驱动，`/` 唤起；`+` 菜单聚合图形入口
  （File/Goal/Plan/Feedback/Compact/Permission/Model/Export）。
- **@ 引用**：文件/会话引用，插入后为 chip 形态随消息发送。
- dsh 无独立 Cmd+K——命令即 `/` 管线。

## 3. AIGoat 改造设计

### 3.1 文件结构

```

├── TriggerManager.tsx     触发符状态机：idle/trigger/selected（≤180）
├── TriggerPopup.tsx       弹层：fuzzy 列表 + 分组 sticky 头（≤180）
├── PlusMenu.tsx           「+」聚合菜单（≤140）
├── SkillCommand.tsx       /skill 目录数据源（≤120）
├── FileReference.tsx      @file：文件 fuzzy + chip 插入（≤160）
├── ReferenceChips.tsx     已插入引用的 chip 行（≤100）

commands/
├── registry.ts            命令注册表：id/标题/分组/派发类型/handler（≤160）
└── builtin.ts             内置命令清单（/plan /goal /compact /model /permission /export）（≤200）
```

### 3.2 触发状态机（照抄 dsh 三态）

```
idle --键入'/'或'@'--> trigger --选择--> selected --继续键入--> trigger
trigger --Esc--> idle；selected --发送--> execute（命令行内执行，不发给模型）
popupSelect 类命令：选择即执行（如 /compact）；execute 类：填参后回车执行
```

- 弹层键盘模型：↑↓ 选择、Enter 确认、Esc 关闭、Tab 补全——与 composer 共享
  焦点（弹层开时拦截 composer 的按键，关闭即归还）。
- fuzzy：简单前缀+子串匹配即可（命令/技能量级 <100，无需引库）；
  分组 sticky 标题（技能按目录分组、文件按工作区相对路径）。
- **@file chip → 发送**：chip 转为消息前缀文本 `[文件] path`（一期）；
  二期若 codex 支持 attachment（11 板块）则图片之外的文件仍走文本引用
  （codex `thread/attachment` 形态以 manifest 为准，17 期核实）。

### 3.3 「+」菜单（图形入口聚合）

项：文件引用、目标、计划、压缩上下文、权限档位、模型、导出。
每项 = 对应命令的 `action` 派发。dsh 的 Feedback 项弃。

### 3.4 Composer 其他升级

- 发送行为设置（Enter 发送 / Shift+Enter 换行——设置中心「通用」域接线）。
- steer：回合运行中输入框切换为「补充指示」模式（发送即 `turn/steer`，
  桥已有 UI 无）——占位提示文案变化 + 图标区分。
- 停止按钮（interrupt 已有）保留在发送键左侧。

### 4.1 实现期确定的四件事

1. **触发符要求"行首或空白之后"**。否则 `a/b`、`src/lib/main.ts` 里的斜杠
   会误触发弹层——这在写路径的时候几乎必然发生。
2. **命令与文件共用一套弹层形状与键盘模型**。两种触发符的状态机完全相同
   （idle/trigger/selected），只有候选来源不同；拆成两套会让键盘行为出现
   分叉。
3. **提交时命中命令就**不**发送**。`popupSelect` / `action` 已经在弹层里
   被消费过，提交时再执行一次等于"没选就执行"——比如把 `/compact` 原样
   发给模型。只有 `execute` 类（`/plan`）在提交时本地执行。
4. **`+` 菜单没有走命令注册表**。它的项与 `/` 的项**并不重合**（`+` 有
   "切换右栏"这种纯界面动作，没有斜杠形式）。两边真重合了再合流。

### 4.2 `@file` 只索引已加载的那几层

深层目录要等用户展开，而"展开某个目录"本身就是他在想什么——提前全量索引
既慢又没帮上忙。候选上限 50 条：装满依赖的目录能出几万条，全渲染会卡死弹层。

# 12 · 审批、用户问答与权限预设

> 抄 dsh：`packages/client/ui-approval/`（接管 composer）＋`ui-user-questions/`（问答卡）＋`ui-permission-presets/`（picker）｜协议：5 审批方法＋requestUserInput＋elicitation＋permissionProfile/list｜决策：**抄**

## 1. dsh 的设计

- **审批接管 composer**：审批请求到达时，整个输入区被审批卡**接管**
  （不是浮层卡片）——Enter 批准 / Esc 拒绝，语义化快捷键；视觉上突出
  （危险操作红色基调 + RiskConfirmation 形态）。
- **用户问答卡**：agent 向用户提问（选项/自由文本/跳过/分页；倒计时；
  过期仍可作答——迟到的答案优于没有）。
- **权限预设**：`/permission` picker（Read Only / Workspace Write / Full）
  ＋设置里选新会话默认。

## 3. AIGoat 改造设计

### 3.1 审批接管（现 ApprovalCard 59 行 → 接管式）

```
components/approval/
├── ApprovalTakeover.tsx   接管 composer 的容器：按 kind 分流（≤160）
├── CommandApproval.tsx    命令审批：命令文本 + 危险参数高亮（≤180）
├── FileChangeApproval.tsx 文件审批：路径 + diff 预览（DiffBlock）（≤160）
├── PermissionsApproval.tsx 权限审批：申请项清单 + 粒度说明（≤140）
├── ElicitationCard.tsx    MCP elicitation：表单形态渲染（≤160）
└── *.module.css
```

- **接管语义**：`store/shell.ts` 的 pendingServerRequest 非空时，
  Composer 区域整体替换为 ApprovalTakeover（draft 文本暂存不清空，
  处理完归还焦点——dsh 的焦点模型）。
- **快捷键**：Enter 批准 / Esc 拒绝 / `Shift+Enter` 查看详情展开。
  危险命令（rm/del/format 等）需 `Shift+Enter` 显式确认而非裸 Enter
  （RiskConfirmation）。
- **批量**：队列内多条审批逐条接管（显示 1/N），不聚合降级。
- 保留现有自动应答策略（Auto 档）逻辑不动——只改呈现层。

### 3.2 用户问答卡（补"有协议无 UI"缺口）

```
components/interaction/
├── UserInputCard.tsx      requestUserInput 渲染：选项/文本/分页（≤200）
├── UserInputForm.tsx      按参数 schema 生成表单控件（≤180）
```

- **关键修复**：`item/tool/requestUserInput` 现走泛化 hostCapability 通道

  回合悬挂风险**。

  倒计时不做（codex 协议无 deadline 字段——协议优先，不虚构）；
  过期（回合已结束）仍可作答的边界：应答前检查回合状态，已结束则提示。

### 4.1 实现的取舍

**① 危险命令要 Shift+Enter，不是裸 Enter。**
在审批框里按 Enter 是肌肉动作，和"确认真的要删掉整个项目"时的心理准备
是两件事。所以危险命令多要一个 modifier。判定在 `danger.ts`：
关键词（`rm`/`format`/`reset --hard`/…）+ 提权 + 通配删除 + 在根目录或
用户主目录上执行的删除。**宁可误报**——漏报的代价是不可逆的数据损失，
误报的代价是用户多按一次 Shift。

**② 全局按键挂在 window 上，焦点在输入框时不抢。**
审批卡不是焦点目标，用户此时压根没在点任何东西，光标可能还留在别处。
但如果用户正在输入框里打字，"rm" 的 r 和 m 就不该被当成快捷键——
所以显式跳过 textarea/input 焦点。

**③ 草稿提到 `ComposerSlot` 里，不放在 Composer 内部。**
审批接管期间 Composer 整个被换掉，草稿在它内部就丢了。提上来之后
组件卸载不带走草稿，回来时内容还在。

**④ 复用消息流里那张 `ApprovalCard`，不写第二份。**
审批只有一条链路上有实现（ingest → 卡片 → 应答命令）。两处各写一张卡，
迟早出现"接管时显示危险、消息流里不显示"的分裂。

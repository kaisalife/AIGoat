# 04 · 消息流与回合

> 抄 dsh：`packages/client/ui-chat/src/client/chat/`（ChatView/MessageItem/ReasoningRow/TurnUsagePanel/TurnNavigator）＋ `ui-conversation/src/client/skeleton/`｜协议：item/* 全量 delta 流＋turn/* ＋tokenUsage｜决策：**抄**

## 1. dsh 的设计

- **过程分组折叠**：连续的工具/推理过程自动归组为可折叠块，组头是活动摘要
  标题（如"Read files and ran commands"），运行中用 TextShimmer 流光。
- **4 档工作详情模式**：概要 → 常规 → 全部细节 → 原始事件（同一事件流四种投影）。
- **turn rail 导航**：右侧悬浮的回合导航条，预览浮于代码块 sticky 头之上。
- **本地回显原子替换**：发送即显（pending 态），权威记录（item/started +
  userMessage item）到达后**原子替换**——断线重连不丢消息。
- **滚动所有权**：尾部跟随与自由阅读显式双模；上滚即暂停跟随、回到底部按钮
  恢复；语义锚点跨分页/重挂载恢复阅读位置。
- **token 用量条**：每回合 TurnUsagePanel；本地回显不显示用量（还没结算）。
- **reasoning**：折叠行 ReasoningRow，`isSummary` 决定标题样式。

## 2. codex 协议支持

全支持：`item/{started,completed}`、`item/agentMessage/delta`、
`item/reasoning/{textDelta,summaryTextDelta,summaryPartAdded}`、
`item/commandExecution/outputDelta`、`item/fileChange/outputDelta`、
`turn/{started,completed,diff/updated,plan/updated,moderationMetadata}`、
`thread/tokenUsage/updated`、`serverRequest/resolved`。

（现有 reducer 已正确，保持）；`item/reasoning/summaryPartAdded` 现被丢弃
（C 期接线，做推理分段标题）。

### 3.2 关键机制

- **Entry 模型扩展**（`store/entries.ts`）：加 `pendingUserMessage`
  （本地回显）与 `processGroup`（归组节点）两类；pending entry 携带
  `clientMsgId`，权威 userMessage item 到达时按 id 原子替换并保留时间戳。
- **归组规则**：同一回合内，连续的 reasoning/toolCall/命令输出 entries 归入
  一个 processGroup；组头摘要标题由组内条目类型推导（"思考并调用了 3 个工具"）。
  归组在 reducer 完成而非渲染时——渲染层只读快照。
- **4 档详情**：`store/ui.ts` 加 `detailLevel: 0|1|2|3`；ProcessGroup 默认
  折叠（0/1 档）/展开（2 档）；3 档透传 Unhandled 原始事件（对接 06 的账本）。
- **滚动所有权**：`useScrollOwnership` 以「距底 < 40px」为跟随态判定；
  离开跟随时记录最近可见 entry 的语义锚点（`entryId`），重挂载/翻页后恢复。
- **turn rail**：TurnRail 从 turns 列表渲染小节点（状态着色），hover 预览
  显示回合摘要（首条用户消息截断 60 字），点击滚动到 TurnBlock。

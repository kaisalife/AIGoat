# 07 · 计划（Plan）与目标（Goal）

> 抄 dsh：`packages/client/ui-plan/`＋`ui-goal/`｜协议：plan 全链已接，goal 协议在、桥未接｜决策：Plan **抄**、Goal **抄**、Todo **弃**

## 1. dsh 的设计

- **Plan**：composer 的蓝色 chip 开关（`/plan` 触发）；计划提交后自动打开
  右栏文档审阅视图；完成后在消息流留计划卡。
- **Goal**：composer 上方的常驻 strip：显示当前目标，可编辑/暂停/恢复/清除；
  `/goal` 命令弹气泡。
- **Todo**：composer 上方面板（Goal 前一张卡）。

## 2. codex 协议支持

| 功能 | 协议 | 状态 |
|---|---|---|
| Plan 全链 | `turn/plan/updated`＋`item/plan/delta`＋`plan` Item | ✅ 已接（PlanPanel 已有） |
| Plan 审阅 | 右栏 tab（宿主侧） | ✅ 本地 |
| Goal 读写 | `thread/goal/{get,set,clear}` | ❌ 桥未接（17 期加 3 命令） |
| Goal 事件 | `thread/goal/{updated,cleared}` | ❌ map.rs 未映射（C 期） |
| Todo | **无对应**——ThreadItem 19 种无 todo，无任何 todo 方法 | **弃** |

Todo 弃用说明：codex 的 `plan` Item（步骤列表带状态）覆盖了"任务清单"诉求；
不本地造一份假 todo（会与模型真实状态脱节）。若后续上游加 todo Item 再启用。

### 4.1 暂停按钮为什么做了

07 号文件写的是"若无 paused 字段则只做清除+编辑"。核实结果是
`ThreadGoalStatus` 里 `paused` **是一个枚举值**，不是布尔字段
（见 [17 号文件 §5.3](17-后端命令层扩展.md)）。协议有就不该不做，
所以暂停/恢复按钮照做。

### 4.2 `ThreadGoalSetParams` 的 null 语义

三个字段（`objective` / `status` / `tokenBudget`）都可选且可为 null，而
**null 的语义是"不动它"，不是"清空"**。想清空必须用 `clear`。

这条很容易踩：前端若图省事把没改的字段也传 `null`，用户点一次"暂停"
就会把目标文本清掉。所以 `tauriConfig.ts` 里只在 patch 真的有那个键时才
往下传，其余一律不发。

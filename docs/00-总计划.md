# 00 · 总计划：按板块移植 dsh 前端设计到 AIGoat

> 任务定义：**抄 DeepSeek Harness（dsh）的前端设计**，一个板块一个功能一份设计文件，
> 用来改造 AIGoat 的前后端，使之后拥有 dsh 的能力。
> 功能边界以 **codex app-server 协议**（`proto/scope.json`，155 项纳入范围）为准——
> dsh 有而 codex 没有的不抄，codex 有而 dsh 没有的择优补。
> dsh 参考代码：`../../dsh/`（zip 拉取，master 分支，只读参考，不引入依赖）。

## 1. 三条铁律

1. **抄皮不抄骨。** 抄布局、交互、视觉与信息架构；不抄 Cordis 插件内核、slot
   插件体系、Typert Remote 传输。AIGoat 的骨架保持 React 18 + zustand +
   Tauri 命令层 + `codex app-server` 子进程。
2. **协议优先。** 每个板块动工前先查 `proto/scope.json`：方法/通知/Item 有对应
   才进范围；没有的写明"codex 无对应"并放弃（见 [18-排除清单](18-排除清单.md)）。
3. **独有功能不丢。** 两个 AIGoat 独有功能必须保留，位置可以挪：
   - **AF 规范子 Agent 接入**（`~/.agent-registry/registry.json` 注册表 +
     `developerInstructions` 派单注入）→ 挪入设置中心「子 Agent」域 +
     会话内子代理展示（见 [09-子代理与AF接入](09-子代理与AF接入.md)）
   - **自定义模型配置**（provider/模型/推理档位/上下文窗口，不用 codex 内置
     模型目录）→ 挪入设置中心「模型」域 + `/model` 选择器数据源
     （见 [14-模型选择与配置](14-模型选择与配置.md)）
   - 工作区（多文件夹管理）为 AIGoat 既有的本地概念，与 dsh Workspaces 对齐保留。

## 3. 现状基线（2026-10 实测，改造的起点）

- 后端：`main.rs` 注册 **42 个 bridge_\* 命令**（README 的"30 个"已过时）。
- 协议消费：client 方法 **19/68**，通知 **约 35/61**，ThreadItem **19/19**。
  未消费的 49 个 client 方法清单见 [17](17-后端命令层扩展.md)。
- 前端已落地：三栏布局、消息流（流式/覆盖）、工具卡、审批卡、diff 卡、计划面板、
  压缩提示、子代理徽章、右栏五面板（手动刷新）、文件树+编辑器、工作区管理。
- 前端断点（有桥无 UI / 有类型无实现）：
  1. `item/tool/call` 到达后前端只插占位**永不应答**——客户端工具闭环断裂；
  2. `client.review()` 已实现**无任何调用点**；steer/fork 同样无入口；
  3. `guardEvent/hostEvent/host4Event` 是纯前端预留类型，Rust 从不产生；
  4. ImageView/ImageGeneration、hookPrompt、functionCallOutput 事件被静默丢弃。
- 超行数文件（用户约束 ≤200 行/文件）：`SettingsDialog.tsx` 850、`shell.tsx` 406、
  `reducer.ts` 383、`events.ts` 295、`tauri.ts` 246、`client.ts` 242、
  `SidebarLeft.tsx` 231、`TopBar.tsx` 205；后端 `commands.rs` 754、`map.rs` 515。
  拆分计划见各板块文件。

## 5. 全局工程约束

- **配置落盘（用户拍板）**：所有配置文件默认存**安装文件夹**（exe 旁）——
  `settings.json` / `workspaces.json` / `ui-state.json` 同一目录；该目录
  不可写（如装进 Program Files）才回落 `%APPDATA%\dev.aigoat.app\` 并自动
  迁移（settings.rs 现有策略，提取为共享 `config_dir()`，见 17）。
  **前端持久化状态一律走配置文件、不用 localStorage**——WebView 的
  localStorage 落在 C 盘 AppData，违背该原则；布局/右栏 dock 等 UI 状态
  统一存 `ui-state.json`（经 `bridge_ui_state_{load,save}` 读写，前端
  500ms 防抖）。
- **行数**：所有源码文件 ≤200 行（用户硬约束）。每个设计文件的「文件预算」
  一节列出拆分后的目标结构，超限即拆。
- **样式**：新组件一律 CSS Modules（Vite 原生支持）＋语义 token；存量全局 CSS
  在触及该板块时迁移。禁 Tailwind、禁组件库（保持零 UI 依赖，对齐 dsh 自研路线）。
- **命名**：token 前缀 `--ag-*`（不搬 dsh 的 `--dsw-*` 名字，只搬双层结构）。
- **协议契约**：前端只依赖 `web/src/bridge/` 的类型；Rust 侧 `map.rs` 是通知→
  AgentEvent 的唯一映射点；新增事件先改 `events.ts`＋`map.rs`，再动 UI。
- **宽容解析**：未建模通知落 `Unhandled` 透传的既有设计不变——上游升级不打断事件流。
- **dsh 参考只读**：`../../dsh/` 不进依赖、不拷代码文件，只对照交互与结构。
